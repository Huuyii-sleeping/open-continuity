# 6C：开关消融与接受决策

先固定这份验收协议，再运行结果。6A原38题及quality-v1标签不变；新增`lexical-fallback-v1` 16题，全是虚构、已暴露的固定验收，不叫盲测。

结果分开看，不混成总分：

| 观察 | OFF与ON对照什么 | 接受条件 |
| --- | --- | --- |
| 原题 | 按题、入口、存储的Recall@1/3/5、MRR、nDCG、miss、false selection | 默认开启不能有任何单题退化 |
| 新题 | 单编辑、字面保护、负例、合法词歧义、语义Challenge分别列出 | 不把合法词歧义改标为正确；新增错误选择阻止默认开启 |
| 权限/事实/引用 | 实际返回、实际候选、独立诊断探测分开 | 三层零泄露；当前版本值与引用一致；保守事实拒绝不变 |
| 稳定性 | 三次重建，每次三个重复 | 同fixture全部顺序一致；重建比label顺序而非随机id |
| 性能 | 同一SQLite库、同权限/预算/工作负载，OFF/ON交错顺序 | 无命中专项三轮P95中位数≤OFF×2+2ms |

性能使用1k、10k虚构记忆，3轮、每轮20次预热+100次正式请求，分别测字面命中、可纠正无字面命中、真正缺失、宽trigram噪声。耗时保存原始样本/P50/P95/P99，不合成一个延迟分数。探测条数限制不保证SQLite硬超时，也不代表生产SLO；噪声成本失败同样阻止默认启用。

“实现工程验证通过”与“建议默认开启”是两个门禁。前者检查报告完整性、错误、安全、版本引用及稳定性；后者还要求质量非退化和专项成本达标。ON的反例失败必须原样展示。默认门禁若失败，保留构造参数显式选择、默认OFF；不提高预算、不放宽权限、不修改Required标准。

不在本阶段实现：中文分词/改写、同义语义召回、跨语言、模型重排、自动事实裁决。现有事实声明与版本引用只证明来源和状态，不证明内容是真实世界真理。
