# Retrieval Core 阶段门

任何阶段都必须独立完成设计、实现、验证和复盘。上一阶段未通过，不进入下一阶段；不能通过一次大改后的总指标反推每一层都正确。

## 每阶段必交证据

报告必须拆分召回、Context、安全、稳定性、容量性能和工程可靠性；不同存储独立、Required/Challenge 独立。没有综合总分。未执行的维度标为未验证，禁止用其它维度的通过结果替代。

1. **职责**：本阶段解决的问题和明确非目标。
2. **契约**：输入、输出、错误、能力版本和兼容策略。
3. **不变量**：user、agent、task、private、userConfirmed、workspace 和审计边界。
4. **变更范围**：修改文件及其所属层，说明为什么没有跨层实现。
5. **测试**：单元、契约、安全、失败和迁移测试。
6. **质量**：阶段对应指标的前后对比。
7. **消融**：关闭新增机制后的结果，用于证明收益归因。
8. **性能**：P50/P95/P99、容量、超时和环境说明。
9. **失败样例**：逐项保留，不通过降标或硬编码抹掉。
10. **能力声明**：implemented、fallback、challenge、roadmap 的更新。
11. **剩余风险**：进入下一阶段前仍接受的风险及理由。
12. **人工确认**：只有评审确认后才开始下一阶段。

## 阶段 1 准入条件：可信存储内核

阶段 1 可以开始，但只允许处理存储职责。进入阶段 2 前必须满足：

- 明确 Storage Contract 是否保留 query 语义，或拆分成纯存储原语。
- InMemory、SQLite、PostgreSQL、JSON 的语义矩阵经评审确认。
- shared conformance suite 覆盖 InMemory。
- 覆盖过滤、稳定分页、幂等冲突、CAS、事务回滚、Forget/History 和迁移。
- 明确 legacy cursor 的跨过滤器兼容策略。
- PostgreSQL 的能力声明与实际实现一致，并区分 pg-mem 与真实环境证据。
- 阶段 1 不引入 BM25、RRF、Embedding、Rerank 或 Answer 行为。

## 阶段 2 准入条件：候选召回

- 每个 Retriever 能独立产生候选并输出明确来源。
- 权限过滤发生在候选返回之前。
- Exact、Structured、Lexical 的职责没有重复计算。
- 每个 Retriever 单独报告 Recall@K、miss rate、P95 和泄露率。
- SQLite 的 FTS5/BM25 与短查询 fallback 分别有确定性测试。
- 不进行跨通道融合，不生成 Answer。

## 阶段 3 准入条件：排序与事实选择

- Evidence Contract 区分 raw score、score model、score direction、channel rank 和 fused score。
- 单 Retriever 直接使用原生排名；多个独立排名才允许融合。
- Exact precedence、boost 上限、RRF 参数和 tie-break 均有契约。
- 新增每个排序信号都有消融实验。
- 报告 MRR、nDCG@K、排序稳定性和当前/旧事实选择准确率。
- 排序版本进入 cursor fingerprint 或有明确兼容演进方案。

## 阶段 4 准入条件：Context 与 Answer

- Recall、Context、Answer 是独立消费者，不共享隐式策略。
- Context 明确 public、userConfirmed、workspace 和预算语义。
- Answer 只使用 Evidence Contract，不能直接扫描 Store。
- 证据不足时有明确 partial/insufficient/abstain 行为。
- 报告 false injection、重复注入、faithfulness、引用覆盖和拒答准确率。
- 所有安全泄露率保持为 0。

## 阶段 5 准入条件：运行可靠性

- 5A/5B/5C独立设计与验收，复用已验证存储/检索，不引入新Adapter或模型。
- 同一请求共享单调deadline；超时不再发新读取；未结束驱动工作仍占槽位。
- 无命中、超时、容量忙碌、存储失败分别可辨；不自动重试未知提交。
- 明确同步SQLite、自定义驱动、关闭drain的边界，不声称硬取消或断电认证。
- 真实进程并发、事务边界退出、幂等重试、版本/FTS/引用及备份恢复独立验证。
- Recall/Context/Query容量与并发原样本分开；固定性能回归规则在测量前声明。
- 原质量标注/Challenge和scope/private/确认边界保持，不用工程成绩替代语义提升。

## 阶段6A：失败归因

阶段6A必须保持生产实现和旧标注/等级不变；记录实际候选与独立诊断重放的区别。完整网格/原值版本/引用/分母需可重算并有伪造反例。开发与固定验收分区独立，已暴露验收不能宣称盲测held-out。输出逐题缺口而非总分；用户后续授权执行整个阶段6后，6B/6C以独立可选策略及固定接受协议推进，未实现的向量/模型能力仍为路线图。

## 阶段6B/6C：有界优化与诚实接受

- 原字面命中集合/顺序保持；fallback仅在原字面全空时触发。
- 原权限/确认先于probe上限，100次检查/8分支/文本上限不可突破；截断不假称穷尽。
- 一次编辑是真实拼写信号，不是语义/置信概率；事实/预算/版本引用规则保持。
- 原38题与新16题独立开关消融，旧标注不改；合法词负例错误不得变成“正确纠错”。
- 1k/10k每workload三轮P95中位数预算`ON≤OFF×2+2ms`，原始慢样本保留。
- 实验完整性和默认启用是两个门禁；质量或成本不满足则默认OFF，不假称优化全部通过。

## 历史 6D 方向：模型辅助查询改写（未实现）

- 人工词对实验已撤销；不维护全局手工同义词典，不把模型方向声明为已实现。
- 优先评估调用方已有Agent模型生成少量子查询，接入现有显式`memory_query.subqueries`；不得保证客户端会自动调用。
- 查询改写不扩大user/agent/task/private/确认边界；原排名、事实拒绝、预算和版本引用继续约束结果。
- 独立模型后端必须可选、默认关闭，外部调用显式批准；明确deadline、fail-open、审计与数据发送边界。
- 固定原标注，独立对照同义/中文/跨语言收益、误召回、安全、稳定性、延迟与成本；无法通过的Challenge继续保留。
- 人工别名已撤销；本轮 7A 只进行模块化，模型改写仍未实现。

## 7A：模块化重构

- 模块内部操作也分别实现和验收；`test:core`按模块/线路生成可核对网格、指纹及分项状态。零断言、缺失/重复结果不能通过，skip不得冒充完整验证。必要事务/预算/调度所有者保持。

- 各 Retriever/backend Reader 独立实现，选择缺失通道必须在读取前明确拒绝；不得伪造能力。
- Core domain 不依赖数据库；Context/Query 依赖窄读取契约；通道不能互相导入。
- 旧入口纯 re-export；旧 Store wrapper/override 保留；新 Reader 也受 deadline/容量约束。
- 旧 schema、指纹、排名与质量标注不变；同评测器跨源码对照，质量、安全、稳定性独立报告。
- 验证新旧游标互续、临时数据库、真实 PG fixture、worker 路径与安装包入口。
- 本轮不接入 Embedding；完成本轮交付后才能独立推进索引与模型增量。

## Embedding 与混合召回：显式实验已实现，默认交付待验收

- 原记忆/事件是权威源，向量是可重建派生索引；不能以索引替代写入审计。
- 写入任务的事务边界、当前版本核对、删除/恢复/重建/模型升级必须单独验证。
- Exact、BM25、Dense 分模块；Structured 和权限/确认在各路候选返回前生效。
- provider、模型、外部发送授权、超时/失败降级、预算和能力声明需明确；不默认上传真实内容。
- 固定原标注，分别报告同义/跨语言收益、误召回、安全、稳定性、延迟和索引成本；失败 Challenge 保留。

当前 SQLite 派生索引、独立 Dense 通道、投影缓存和可选本地模型验证已完成实验接入；默认工厂与公开配置继续关闭模型。模型不可用、索引不完整及 Query 超时不得计为正确负例。验收仍有误拒绝、错选、冷加载及较强验证模型资源超标；模型安装、跨平台和独立盲测尚未完成，不能通过实验工程门禁宣称默认语义能力成熟。详见 [接入](./embedding-integration.md)与[优化验收](./embedding-optimization-validation.md)。
