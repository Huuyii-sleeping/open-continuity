# 双向补召回验收

本次是显式 Embedding 实验的有限质量增量，默认 Lite 不变。Before 为本分支自己的冻结工作区，已经包含上一轮 SQLite 字面索引优化；没有把上一轮 5/14→14/14 的字面收益再次计入语义改进。

## 失败对照：保留问题

| 被放弃的方案 | 实际问题 |
| --- | --- |
| 去掉score gate，前四候选只有单向支持且唯一才准入 | 旧四组正例28/43→27/43；无答案误召回0/29→4/29 |
| 保留score gate，但直接验证并加入四条 | 旧 quality 正例11/12→9/12，新增不相关条目 |
| 保留旧命中，仅凭窗口双向支持补召回 | 新24题找回一个正例，同时新增3/12无答案误召回 |
| 最终：增加首候选矛盾停止 | 新误召回回到0/12，保留两组各一个新正例 |

模型可能把不相关内容判成双向支持；它不是可靠的通用问句 reranker。当前规则有预算、可追溯并且保守，仍需要独立盲测和更合适的问题相关性验证。

## 性能：收益的成本

真实模型质量配对中，将各组原始耗时合并后计算每轮P95，再取三轮中位数。模型已预备，索引已计算；下列数字不是冷启动。

| 出口/阶段 | Before P95 ms | After P95 ms |
| --- | --- | --- |
| Recall 全部响应 | 14.946 | 45.820 |
| 索引/模型准备后每题首个 Recall | 17.607 | 60.723 |
| Recall 的重复响应 | 3.137 | 3.280 |
| Context 全部响应 | 2.897 | 2.971 |
| Query 全部响应 | 2.931 | 3.083 |

Context/Query在Recall之后测量，可能复用其验证缓存；不能用它们的低耗时宣称模型推理变快。额外比较最多四个候选、最多八次方向推理；相同输入重复查询可复用有界判断缓存。

模型资源另采样：十组各自的embedding/verifier所有者正常关闭，没有网络请求。Embedding进程峰值约197.6–202.0MiB；NLI约476.9–488.7MiB，仍超过此前350MiB目标。各进程RSS不是独占物理内存；本轮没有优化模型驻留成本。

默认无模型的10k Lite benchmark另做三轮交错配对，各100次查询。Exact P95中位数2.045→1.863ms，FTS 3.814→4.059ms，Context 3.809→3.684ms；写入总时间8697→8862ms。保留首轮Before Exact 6.253ms的异常高值和全部分项，不按结果删样本；默认算法未改，不宣称本轮给它提速。

## 复现与范围

使用[设计页](./dense-rescue.md)的显式Core配置及 `eval:dense --compare-rescue`。provider/verifier必须指向用户已准备、校验的本地模型模块；没有自动下载或生产 inference 依赖。完整事件账本、冻结数据集hash、逐题结果、每次耗时、失败对照、分模块报告和原始日志保存在本轮仓库外验收目录，不提交数据库、权重或日志。

本机证据为macOS ARM64、Node 24.20.0。远端Ubuntu/macOS×Node22/24 CI、独立盲测、用户安装、生产流量与通用问题相关性尚未验证；默认开启条件仍不满足。本轮未commit或push。
