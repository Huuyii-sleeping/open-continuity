# 相关性重排：分项验收

本轮交付显式 Dense 候选重排，默认 Lite 仍不加载模型。旧五组正例通过从39/55变为41/55，修复两个旧错选；无答案误召回保持0/41。新噪声池没有额外收益，支持验证仍误拒绝部分自然问句，完整模型组合约1GB，继续作为实验能力。

## 对照与来源

Before 是本轮开始时完整的本工作区源码快照，包含前一轮 SQLite 字面索引和双向补召回。它不是旧发布版本，也没有复制其它工作区。After 冻结最终运行算法；两侧共用升级后的同一评测器，以支持超过100条记忆的分批索引。模型不可用、无进展索引、绑定错误、代次变化和 deadline 均拒绝计分。

原五组标注、原模型、余弦0.62/margin0.14与NLI0.5/0.5保持。新增 `reranking-window-challenge-v1.json` 每题使用248条完全虚构记忆，16题（8正/8负），在首次模型推理前冻结。SHA-256为 `ee607c2383c33c4c2e009d1f0361fdd4d557c9ea79c82dc729790909cb5f229b`。作者生成、已暴露的回归数据不是独立盲测。

三轮新进程交错配对（B→A、A→B、B→A），同组共用ID/事件/版本/时间戳，每个 Recall、Context、Query 出口重复三次。最终三轮使用同一冻结算法，选择与判断全部一致；早期版本的首轮另存，没有混入最终成绩。

## 最终质量

以下是每轮的实际题数，没有把重复三次扩成三倍独立样本。三个出口结果相同，逐出口原始报告分别保留。

| 固定数据集 | 正例 Before | 正例 After | 无答案误召回，两侧 |
| --- | ---: | ---: | ---: |
| quality-v1 检索部分 | 11/12 | 11/12 | 0/2 |
| dense-admission-regression-v1 | 6/11 | 6/11 | 0/7 |
| dense-pair-regression-v1 | 6/12 | 6/12 | 0/12 |
| dense-verifier-challenge-v1 | 6/8 | 7/8 | 0/8 |
| dense-rescue-challenge-v1 | 10/12 | 11/12 | 0/12 |
| **原五组** | **39/55（70.9%）** | **41/55（74.5%）** | **0/41** |
| 新248条候选噪声池 | 7/8 | 7/8 | 0/8 |

原五组 Recall@1、Recall@5、MRR 同为0.7091→0.7455。当前最终线路最多采用一条 Dense 证据，三个数字相等不能证明多文档排名已成熟。Miss rate 为16/55→14/55。已选择内容的 false selection 为2/41→0/41；这与无答案误召回0/41是不同分母。新池上述排名指标均为0.875，miss1/8，没有新收益。

加入新池后的63正/49负总计：正例46/63→48/63，错选2/48→0/48，无答案误召回0/49。该总数仅作汇总，不能代替旧池与新池的独立结论。

两处改变可具体复核：

| 问题 | Before | After | 含义 |
| --- | --- | --- | --- |
| `fresh-handoff` | `brief` | `handoff` | 把任务交接与简短回答候选分开 |
| `rescue-permit` | `confirm` | `permit` | 把授权目录与批准存储候选分开 |

其它题的选择保持，没有新增退化。最终仍有15道正例失败（旧池14、新池1），全部为空结果，保留为 Challenge：短查询、高度相似干扰、批准/目录/回执改写、自然问句和双向支持不足。没有为这些题硬编码答案或调整标注。

## 安全与稳定性

模型评测显式权限题是0/2，三轮各出口选择稳定112/112。新噪声池没有权限题，安全率应为 `null`，不能写0/0通过。跨用户、Agent、task、private、未确认内容另由工程契约测试验证，在模型前过滤；模型分数不批准数据，也不裁决事实真伪。

原默认 `eval:quality` 保持 Required15/15、Challenge9/42、总24/57，安全0/6。原 `eval:suite` 保持185/185，安全0/40。它们验证默认链路，不能借显式实验的74.5%宣称默认产品召回率提高。

## 延迟与资源

本机 macOS ARM64、Node24、CPU2。模型准备、真实模型推理、首次请求和缓存命中分开。质量池的“首次”是每题模型已准备、该查询未命中判断缓存的首次 Recall；它不包含模型安装/加载或索引构建。

| 质量池 Recall | Before | After |
| --- | ---: | ---: |
| 三轮首次 P95 | 57.62 / 58.63 / 63.35ms | 109.22 / 103.92 / 104.02ms |
| 首次 P95 中位数 | 58.63ms | 104.02ms |
| 三轮重复 P95 | 3.76 / 3.79 / 3.56ms | 3.96 / 3.79 / 3.80ms |
| 重复 P95 中位数 | 3.76ms | 3.80ms |

18个最终质量排序会话实际执行354次模型评分，计算时间P50为42.24ms、P95为62.19ms；排序会话准备约366–529ms。单排序进程峰值约196–272MiB，推理网络尝试为0。重复请求的低耗时来自缓存，不能当作模型速度。

另用1k/10k虚构数据库，三轮新进程交错、每臂5预热+50重复请求。每个容量的两侧共享同一事件账本；相同正文复用真实模型向量，不代表不同文档的建索引吞吐。完整 Context 首次请求包含 Embedding 进程加载，提前准备的排序/验证加载另计；与上表“每题首次 Recall”不同。

| --- | ---: | ---: |
| 1k 热 Context P95 | 4.43ms | 4.11ms |
| 10k 热 Context P95 | 12.82ms | 11.80ms |
| 1k 首次 Context | 503.74ms | 556.26ms |

RSS 是一次请求循环完成后同一时刻的主进程/子进程相加，含开发tsx、SQLite及测量开销，不是各进程历史maxRSS相加，也不是连续采样峰值。After实测最大同时驻留约1038MiB。热样本的波动不作为模型加速结论；原350MiB个人版预算仍不通过。此配置不宜默认开启。

默认无模型 `benchmark:lite` 独立做三轮10k/100请求，P95中位数：Exact2.373→2.363ms，FTS4.075→4.017ms，Context4.067→4.088ms；建库写入总时长9015.99→8992.89ms。没有明显默认性能变化，也不把小幅波动称作优化收益。

## 工程与失败边界

- `typecheck`、架构门禁（207个源码、799条边、0违规）通过。
- 三轮 `npm test`（普通+两轮乱序）每轮802通过、60条件跳过；跳过不算通过，包含未启用的真实PostgreSQL夹具。
- 分模块报告121条线路，710通过、60跳过；排序模型9、纯排序/选择2、Dense组合9分别通过。
- `eval:suite`、`eval:quality`、package smoke、1000循环可靠性soak通过。所用夹具完全虚构，没有读取真实Agent历史或默认数据库。
- timeout保留真实未完成容量；迟到输出不缓存，关闭等实际drain。评分数组不完整、非finite、身份变化、错绑版本/访问/正文、索引更新均不能作为成功回退。
- 依赖门禁另阻止通用排序器依赖Dense准入/上层消费者，阻止纯排序/选择依赖模型运行实现，避免后续模块重新耦合。

增补依赖规则后再次运行typecheck、架构门禁、全量测试、分模块测试和package smoke，结果保持通过；最终分项源码指纹见 `reports/modules-final/`。全部当前未提交文本另经Gitleaks扫描，0发现；扫描不代替后续提交时的来源/授权复核。

本轮未新增生产推理依赖，未修改Adapter，未提交或推送；未运行远端CI或宣称跨平台模型验证。

## 模型探索与未采用方案

最终 Embedding 保持原 MiniLM，支持验证保持原强NLI。新增公开 [MMARCO Cross-Encoder](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1) 只做相对相关性排序；Apache-2.0、固定revision `1427fd652930e4ba29e8149678df786c240d8825`，qint8 ARM64 ONNX SHA-256 `1825907d6c1a9001ff78124780bbde20a614a8c3df3b63409cf3c72c6fe5c8b4`。6个公开文件约136MB均校验大小/hash，权重保存在仓库外。外置87个tensor前后192组评分最大差为0，没有训练或更改模型值。

排序诊断曾把正确候选放首位52/55，但29/41负例也有正logit。不能把前者写作最终召回率，也不能用logit零点作支持门槛。零点+NLI探索只有37/55，未采用。

替换 [multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small) 的探索虽然达到43/55，仍发生两个新错选，未采用。它的查询/正文前缀与相似度分布不同，不能把MiniLM门槛当作已校准。首次实验有模型指纹环境配置失败，作为执行失败保留。

直接替换旧顺序会损失旧正确事实选择；最终保存原已验证基线，重排验证最高候选，正常拒绝时保留基线。排序不可用仍是失败。早期失败保留日志和诊断，部分初始响应曾被探索脚本覆盖，不能宣称所有早期raw响应完整保留。

下一步主要缺口是通用问题支持验证、排序模型成本、独立更大规模盲测与模型安装/跨平台交付。本轮没有自动查询改写、人工同义词表、模型事实裁决或默认全通道重排。
