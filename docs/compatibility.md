# Agent compatibility

The connector matrix records the supported integration contract. A detected CLI is not automatically modified; users run `open-continuity connect <agent>` explicitly. Existing MCP entries are never replaced unless `--force` is supplied, and the connector backs up the client configuration first.

| Client | Integration | Connector | Identity binding | Current verification |
| --- | --- | --- | --- | --- |
| Trae | MCP stdio + app-server Capture + experimental UserPromptSubmit Injection | `setup trae`; `doctor trae`; granular `capture`/`injection` commands | shared local user + `trae` Agent | 真实 `traecli 0.208.1` app-server 初始化和只读 thread 读取探针通过；虚构进程级黑盒覆盖 setup→Capture→审核→已安装 Hook→MCP stdio；纵向 E2E 覆盖轻量注入后显式 MCP 深搜 |
| Claude Code | MCP stdio, user scope | `connect claude` | shared local user + `claude` Agent | command contract implemented; real smoke test requires Claude Code installed |
| Codex CLI | MCP stdio | `connect codex` | shared local user + `codex` Agent | automated isolated connector test; real smoke test depends on working client authentication |

Other products can use the documented MCP stdio command or HTTP API. A client must support custom MCP servers or another extension mechanism. OpenContinuity cannot inject itself into a closed product that exposes neither capability.

MCP server instructions advise capable clients to retrieve relevant context at task start, store only durable information, and create a Handoff Capsule on explicit handoff. The client model and its tool policy still decide whether a tool is called, so tool availability is not a guarantee of automatic invocation.

Trae Conversation Capture is a separate experimental path. It reads only content exposed by the local Trae app-server, skips ephemeral side threads during list-based sync, and stages the visible thread in a local Inbox. The current real read probe verified that a visible local thread can be read with user messages, assistant messages, tool calls, compaction markers, and complete-turn status; it reports structure only and does not persist the user's real thread during verification. List-based sync supports app-server pagination, a configurable page size and maximum thread bound, and reports truncation instead of silently claiming a complete scan. The capture watch command performs interruptible foreground polling and reads threads whose update time differs from the durable per-thread checkpoint. Each successful Inbox import advances thread/turn/item watermarks in the same SQLite transaction; failed imports do not advance them. On macOS, `setup trae` manages the per-user launchd service, reloads it after config or installed runtime changes, and exposes layered health through `doctor trae`. Where launchd is unavailable, setup reports that `capture watch` needs a local process manager instead of pretending a background service exists. The generated plist carries only a small environment allowlist and explicitly includes the detected Trae executable directory, because launchd does not inherit the interactive shell PATH. Sync uses a single-instance lock, stale-lock recovery, bounded retry backoff, and persisted success/failure health state. It does not expose hidden reasoning and does not automatically promote candidates into long-term memory. Claude Code and Codex capture adapters are not implemented.

Trae Injection is also opt-in and local-only. `setup trae --workspace <path>` enables only that workspace, backs up and updates the discovered `hooks.json`, and connects MCP without enabling a global permission bypass. The hook injects only approved public memory, has a bounded local lookup, records no Prompt body, and fails open on timeout or storage errors. Trae does not expose a reliable non-interactive Hook trust state, so `doctor trae` keeps `/hooks` trust and MCP approval as explicit manual checks. The vertical test verifies that the light pack can be followed by an explicit MCP `memory_query` multi-step search against the same shared database; MCP tool invocation remains a decision made by Trae and its model/tool policy, not by the hook.
