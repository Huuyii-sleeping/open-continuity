# Agent compatibility

当前兼容性工作的重点是“共享记忆的入口与出口 Adapter”，不是简单判断客户端是否能连接 MCP。Capture 负责读取本机 Agent 公开扩展面暴露的可观测对话，Injection 负责把已批准记忆带回下一轮 Prompt，MCP 负责按需深度查询和交接。Trae、Claude Code 与 Codex CLI 已验证同一通用 Adapter 契约的三种不同实现。

The connector matrix records the supported integration contract. A detected CLI is not automatically modified; users run `open-continuity connect <agent>` explicitly. Existing MCP entries are never replaced unless `--force` is supplied, and the connector backs up the client configuration first.

## Adapter development status

The Trae, Claude Code, and Codex Adapter milestone is feature-frozen for the current beta and now operates in maintenance mode. The shared contract, per-Agent permission boundary, incremental Capture checkpoints, bounded Injection, managed Hook lifecycle, compensating setup transaction, fictional process black boxes, soak tests, quality gates, and installed-package smoke are complete for the stated compatibility matrix.

Adapter development should reopen only when at least one of these evidence-based triggers exists:

- a supported real client version breaks a documented Capture, Injection, MCP, setup, doctor, upgrade, or uninstall path;
- a security, workspace-isolation, data-corruption, checkpoint, or configuration-restoration defect is reproduced;
- a new Agent with a public extension surface is intentionally added;
- measured reliability data shows that a backlog item is causing user-visible failures.

The credential-backed Claude Stop/non-empty Injection smoke remains a verification task, not a reason to redesign the Adapter. Per-thread batch failure isolation, cross-process Receipt serialization, cancellable Injection lookup, and deeper executable provenance checks remain non-blocking backlog items until real failure evidence raises their priority. New feature work should primarily move to Core while these Adapters receive compatibility fixes and real-client regression coverage.

Other products can use the documented MCP stdio command or HTTP API. A client must support custom MCP servers or another extension mechanism. OpenContinuity cannot inject itself into a closed product that exposes neither capability.

MCP server instructions advise capable clients to retrieve relevant context at task start, store only durable information, and create a Handoff Capsule on explicit handoff. The client model and its tool policy still decide whether a tool is called, so tool availability is not a guarantee of automatic invocation.

Trae Conversation Capture reads only content exposed by the local Trae app-server, skips ephemeral side threads and non-allowlisted workspaces during list-based sync, and stages the visible thread in a local Inbox. The current real read probe verified that a visible local thread can be read with user messages, assistant messages, tool calls, compaction markers, and complete-turn status; it reports structure only and does not persist the user's real thread during verification. List-based sync supports app-server pagination, a configurable page size and maximum thread bound, and reports truncation instead of silently claiming a complete scan. The capture watch command performs interruptible foreground polling and reads threads whose update time differs from the durable per-thread checkpoint. Each successful Inbox import advances thread/turn/item watermarks in the same SQLite transaction; failed imports do not advance them. On macOS, `setup trae` manages the per-user launchd service, reloads it after config or installed runtime changes, and exposes layered health through `doctor trae`. Where launchd is unavailable, setup reports that `capture watch` needs a local process manager instead of pretending a background service exists. The generated plist carries only a small environment allowlist and explicitly includes the detected Trae executable directory, because launchd does not inherit the interactive shell PATH. Sync uses a single-instance lock, stale-lock recovery, bounded retry backoff, and persisted success/failure health state. It does not expose hidden reasoning and does not automatically promote candidates into long-term memory.

Trae Injection is also opt-in and local-only. `setup trae --workspace <path>` enables only that workspace, backs up and updates the discovered `hooks.json`, and connects MCP without enabling a global permission bypass. The hook injects only approved public memory, has a bounded local lookup, records no Prompt body, and fails open on timeout or storage errors. Trae does not expose a reliable non-interactive Hook trust state, so `doctor trae` keeps `/hooks` trust and MCP approval as explicit manual checks. The vertical test verifies that the light pack can be followed by an explicit MCP `memory_query` multi-step search against the same shared database; MCP tool invocation remains a decision made by Trae and its model/tool policy, not by the hook.

Claude Code uses only its documented user-level Hook surface. `setup claude --workspace <path>` preserves existing `settings.json` content, writes a backup before mutation, and installs exec-form handlers for `UserPromptSubmit` and `Stop`. The Stop Adapter parses the JSONL transcript, filters OpenContinuity's own injected context and meta/sidechain records, applies the workspace allowlist to individual records, and uses `last_assistant_message` to cover asynchronous transcript lag. Capture is event-driven and therefore needs no watcher service. Active Claude sessions must be restarted after setup so the user-level Hooks are reloaded. OpenContinuity does not disable normal MCP approval.

Codex CLI uses its local `codex app-server --stdio` JSON-RPC surface for Capture. The Adapter initializes the server, lists threads, reads a selected thread and hydrates turns through `thread/turns/list` (with a legacy `thread/read` fallback), then normalizes user/assistant/tool/compaction items into the shared Inbox contract. Reasoning items are retained only as type markers and their content is never persisted. `setup codex --workspace <path>` installs backed-up, idempotent handlers in `$CODEX_HOME/hooks.json` (normally `~/.codex/hooks.json`): `Stop` triggers Capture and `UserPromptSubmit` returns a bounded approved-memory context. Active Codex sessions must be restarted after setup, and the user must open Codex `/hooks` and trust both handlers. The local app-server probe verifies protocol shape and metadata only; it is not a substitute for a real completed Codex turn invoking both hooks.

All three Capture implementations write the same normalized thread/turn/item contract. The provider-neutral read contract passes the previous durable checkpoint to every Adapter; an Adapter may return a full snapshot or a cursor-backed delta, but a delta must return the exact base cursor together with its next cursor. The orchestration layer rejects mismatched source/thread identities and cursor lineage before Inbox import. Claude transcript Capture stores an opaque byte cursor with file identity and a bounded prefix fingerprint, resumes from the end of the last stable JSONL read (including transcripts shorter than the fingerprint window), and falls back to a full scan when the file is rotated, truncated, observably rewritten, or unstable. Codex and Trae currently return full app-server snapshots and still benefit from the same transactional checkpoint contract. App-server pagination rejects repeated cursors and is bounded so a malformed source cannot loop forever.

Raw turns are filtered before import and cleaned by turn age after import, with a default 7-day window. Candidate evidence is separate, defaults to a 30-day pending lifetime, and must be approved before entering long-term shared memory. Exact candidates from different Agents merge their occurrence evidence; deterministic high similarity creates a review warning, and replacement requires an explicit target so the existing memory evolves to a new auditable version. This is conservative duplicate/conflict protection, not model-based semantic reconciliation.

All Injection Adapters use one shared untrusted-memory envelope. Memory text is escaped before it enters the envelope so it cannot synthesize an envelope-closing tag. The configured token budget covers both the selected memory lines and that envelope; the runtime also limits the number of memories, requires approved public visibility, and returns a fail-open empty Hook output when the final rendered payload cannot fit or the lookup exceeds its timeout. Receipts retain only a prompt fingerprint, selected IDs, reasons, timing, and outcome. Granular Injection management accepts `--agent trae|claude|codex` and resolves the implementation through the shared Adapter registry.

Capture and Injection enablement and workspace allowlists are stored per Adapter. Configuration v1 is migrated to v2 with a backup; legacy permissions are assigned only to explicitly connected Agents (or Trae when the old configuration has no owner), never broadcast to all three. Hook installation records an ownership manifest, reconciles stale OpenContinuity runtime paths, and removes only owned/marked handlers during uninstall. All three setup commands execute a reported plan/apply/verify transaction and run reverse-order compensation when a later MCP, Hook, configuration, service, or doctor step fails.

The Codex Adapter remains experimental: it depends on the locally installed app-server protocol and Codex Hook trust state. A real persisted `codex exec` smoke verified UserPromptSubmit injection and Stop Capture through app-server with fictional data, and a real interactive `/hooks → Trust all → prompt` smoke verified the normal trusted-session path. The automated injection assertion used Codex's one-shot `--dangerously-bypass-hook-trust`; new Codex processes may still require their own `/hooks` review depending on the client's trust lifecycle. If a Codex build does not expose `app-server`, the connector falls back to MCP-only compatibility and refuses Capture setup.
